The problem

Harvest now, decrypt later.

Shor's algorithm

Asymmetric crypto falls entirely

RSA, ECDSA, ECDH, Ed25519 drop to zero bits of post-quantum strength. Everything they ever encrypted or signed is exposed.

Grover's algorithm

Symmetric strength halves

AES-128 keeps ~64 bits of margin. AES-256 and SHA-384 stay comfortable. The answer differs per algorithm, not per vibe.

Mosca's inequality

Some data is already lost

If shelf-life + migration time exceeds years-until-CRQC, adversaries harvesting ciphertext today win before you finish migrating.

Why this is not a regex grepper

Four things carry the weight.

01

Every artefact records file:line, snippet, container layer or binary section. Nothing exists without provenance you can click.

04

A programme, not a list

Mosca simulator — the honest chart

Nobody knows the CRQC year. So show the curve.

Move CRQC year, shelf-life, migration time and headcount; findings flip instantly. Presets: CNSA 2033, Aggressive 2030, Median 2035, Long-lived. The shape of the curve is the deliverable — never a single point estimate presented as fact.

Roadmap — dependency order beats severity order

Migrate in the order physics demands.

W1Kill classically-broken — MD5, SHA-1, RC4… exploitable todayfirst
W2Providers — libraries, binaries, images must support PQC firstunblocks all
W3Protocol floors — TLS versions, configs, endpoints—
W4–W5Key agreement → signatures & certs — the Shor surface, HNDL-firstbulk
W6–W7Vendor-gated + symmetric hardening — HSM/cloud, then AES-128 → 256last
